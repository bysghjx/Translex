# Translex Style Protocol（TSP）

版本：Draft 1

## 1. 概述

TSP（Translex Style Protocol，Translex 样式协议）是一种为 AI 辅助翻译设计的轻量级富文本传输协议。

它的目的是在允许大语言模型（LLM）自由调整句子结构的同时，保留文本样式。

TSP 将样式绑定到内容，而不是绑定到内容所在的位置。

---

## 2. 设计目标

G1. 样式跟随内容，而不是跟随位置。

G2. LLM 不需要理解样式。

G3. 协议独立于 Minecraft。

G4. 协议具有确定性。

G5. 协议能够自校验。

G6. 解码器能够从格式错误的输入中平稳恢复。

---

## 3. 样式注册表

样式信息绝不会发送给 LLM。

每个翻译请求都拥有一个本地样式注册表（Style Registry）。

示例：

```text
ID -> 样式

0 -> 灰色
1 -> 绿色
2 -> 青色
3 -> 金色
```

注册表只在编码和解码期间存在。

编码器应当对相同的 Style 对象进行去重。

---

## 4. Token 格式

Draft 1 使用以下语法：

```text
[[ID||TEXT]]
```

示例：

```text
有 [[1||56%]] 的概率获得 [[2||❄ 寒冷]]。
```

LLM 可以自由移动 Token。

LLM 绝不能修改：

- 开始方括号
- 结束方括号
- 分隔符
- ID

只有 TEXT 部分应当被翻译。

---

## 5. 编码

编码器遍历带样式的文本。

对于每个样式片段：

- 查询样式注册表
- 如有需要则分配 ID
- 输出 Token

纯文本保持不变。

---

## 6. 解码

解码器接收：

- 编码后的文本
- 本地样式注册表

解码器通过将每个 Token 替换为对应的样式，重建带样式的文本。

未知 ID 回退到 `Style.EMPTY`。

---

## 7. 解析器

解析器校验：

- 分隔符是否成对
- ID 是否为数字
- 分隔符 `||` 是否有效
- 是否存在嵌套 Token

解析器会报告解析错误，而不是直接崩溃。

---

## 8. 恢复

Draft 1 的恢复机制有意保持简单。

格式错误的 Token 会被当作纯文本处理。

解析器会继续解析剩余内容。

协议不实现语义级恢复。

---

## 9. 确定性

对于相同的输入：

编码器必须始终生成相同的输出。

样式 ID 按照样式首次出现的顺序分配。

样式去重应当保留插入顺序。

---

## 10. 非目标

TSP 不定义：

- Prompt 设计
- 翻译质量
- OpenAI 集成
- Minecraft 渲染
- 缓存实现
- 网络协议

TSP 只定义样式传输。

---

## 11. 未来扩展

未来版本可能支持：

- 粗体
- 斜体
- 点击事件
- 悬浮事件
- 字体
- 转义序列
- 协议版本头

这些内容不属于 Draft 1。
